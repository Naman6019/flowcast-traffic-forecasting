## Defects found and how they were resolved

| Defect | Entries | Resolution |
|---|---:|---|
| Duplicate log rows | 1,767 | Deduplicated on `road_id + timestamp`, keeping the most complete row. |
| Absent windows | 4,499 | Reindexed to the full grid. Short gaps time-interpolated, longer gaps use training-date medians. These rows never count as targets or in metrics. |
| Null or negative volume | 4,587 | Rebuilt from `vehicle_count`, which equals volume on every valid row. |
| Null, zero or above-200 speed | 4,579 | Rebuilt as `seg_length_km x 60 / travel_time`. |
| Occupancy above 100% | 229 | Blanked, then time-interpolated within the segment. |
| Blank congestion label | 31,123 | Every label recomputed from cleaned volume using the Data Dictionary bands. |
| Congestion label disagreeing with the rule | 0 | Replaced by the recomputed label. |
| Inconsistent weather labels | 3,355 | Lower-cased, stripped and mapped through `config.yaml`. An unknown label raises an error. |
| Null temperature, visibility or rainfall | 278 | Time-interpolated within the station. |

Mixed date formats are parsed explicitly: weather as `DD/MM/YYYY`, traffic and calendar as `YYYY-MM-DD`, all
to tz-aware Asia/Kolkata timestamps. Each hour's weather is applied to both of its 30-minute windows.

Statistical outliers (|z| > 4 per segment, or outside the 1.5 x IQR fence per segment x hour) are flagged
and never changed. Traffic has real peaks and incidents, and these are legitimate rows, so the field policy is to keep them.
